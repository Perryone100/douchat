## 本地客户端回退

先等待任务结束并退出开发客户端。进入实际启动的源码目录，用 `git status --short` 检查工作区；
如有改动，先保存到自己的提交或另存，不使用 `reset --hard` 清除。
远程名称需对应本 Fork；以下以 `perry` 为例，新克隆目录通常为 `origin`。

```sh
git fetch perry --tags
git switch --detach perry/stable-before-context-20261014
npm run dev
```

本次依赖没有改变，已有依赖可直接使用。此前通过带代理环境的启动脚本运行的用户，
切换版本后继续使用同一个脚本启动，避免把环境差异误当作代码问题。
分离 HEAD 用于运行固定版本；若要在旧版上继续开发，先 `git switch -c <新分支名>`。

再次升级时，退出客户端并切换到已验证的新标签：

```sh
git switch --detach perry/context-checkpoints-20261014
npm run dev
```

## 撤回仓库中的改动

若只是暂时运行旧版，使用上述标签即可，不需要改动远程分支。
若决定从代码历史正式撤回此次上下文更新，则从需要撤回的分支创建新的回退分支，
审查两个标签之间的提交，再用 `git revert` 生成反向提交并开 PR。不要强推或删除原提交。

```sh
git log --oneline perry/stable-before-context-20261014..perry/context-checkpoints-20261014
```

此范围包括中间的 `e000668`（旧回合裁剪方案）和随后替换为交接摘要的提交。
完整撤回本次上下文更新需要同时撤回这两项，按从新到旧的顺序进行；
只撤回最后一项会恢复中间裁剪方案，不能达到此次回退点。
后续若又有提交依赖这些改动，应先解决依赖和冲突，再跑对应测试。
