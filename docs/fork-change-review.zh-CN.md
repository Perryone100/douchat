# Fork 改动审查

审查日期：2026-10-15。基线为作者 v0.1.24（`806316a`），已运行的 Fork 为 `b6b1399`。此次只修复 DeepSeek JSON 请求缺少格式指令的问题，并补充回归测试；没有改动协作流程、重试次数或上下文压缩策略。

## 已有改动的依据和处理

| 改动 | 已核对的依据 | 当前处理 |
| --- | --- | --- |
| 流式规划、按有效进度判断停滞 | 原版自定义模型规划不读流式进度；成员尝试固定 60 秒，独立决策请求另有 40 秒期限。仍在生成的请求也会被终止。 | 保留；继续保留 180 秒总预算、取消和迟到结果丢弃。 |
| 请求错误不进入输出格式纠正 | 原版会把部分接口错误当作可修正的计划格式错误，重复请求不能修复接口故障。 | 保留；传输失败与合法响应的结构错误分别处理。 |
| 同一失败服务和模型不重复尝试 | 换成员人设不一定改变模型服务，超时后重复请求同一服务可能耗尽整轮预算。 | 保留现有范围；请求内容导致的 HTTP 错误与服务整体不可用并不等价，后续不能凭一条 400 日志扩大屏蔽范围。 |
| 跳过首次个人发言分类 | 原先可能先分类再完整规划；移除该步骤减少一次前置请求，但改变了模型看到的决策任务。 | 作为策略优化单独记录，暂不来回切换；不能声称与原版语义完全等价。 |
| DS 规划使用低推理和 JSON 模式 | 这是服务商参数选择，不是识别流式进度的必要条件。 | 保留既有设置，仅补齐已经确认缺失的 JSON 指令；不扩大到其他服务或正式工作回复。 |
| 上下文去重、预算和交接摘要 | 已有 SDK 测试复现长上下文将输出预算压到 1；原版持续复用会话会重复加入近期群聊背景。 | 与规划修复分开保留。摘要的事实完整性不能由模拟测试证明，仍需独立质量验证；本次不改变其策略。 |

## 此次修复的范围

作者原版没有为 DS 设置 `response_format: json_object`。Fork 新增该参数后，“不回复”二次确认仍使用不含 JSON 字样的旧提示词，与 [DeepSeek JSON 模式要求](https://api-docs.deepseek.com/guides/json_mode/) 不符。

修复在请求构造处维持一个条件：只有 OpenAI 协议、官方 `api.deepseek.com` 地址且请求携带结构约束时，才附加明确的 JSON 输出指令。模型选择、输出上限、推理档位、格式参数、计划校验、二次确认及故障切换均沿用现有逻辑。普通文本探测、OpenRouter 和其他兼容接口保持原有请求。

这不等于已经确认历史截图中那次 HTTP 400 的唯一原因。历史记录缺少服务端错误正文；离线测试确认的是出站请求违反接口要求，以及修改后的控制流程，不能替代真实服务的错误回执。

## 验证方式

- 使用固定合法模型响应捕获真实请求，不让模拟服务预设“缺少 JSON 就返回 400”。修复前，新增的 6 个 DS 二次确认场景因请求缺少 JSON 指令失败；其余 5 个兼容场景通过。
- 同一组测试在修复后检查 DS 根地址、`/v1` 地址、不同模型名，以及二次确认后保持不回复或重新规划的路径。
- 其他兼容接口、Anthropic、OpenRouter 的结构化输出与原有降级、DS 普通文本探测按完整请求体比较。
- 修复后新增的 11 个场景全部通过；完整回归 1,424 项通过、4 项跳过，类型检查和构建通过。测试不调用真实付费模型。测试覆盖范围不等于全部线上情况，也不能证明真实模型的输出质量不变。

## 后续变更边界

每次故障先区分请求构造、模型返回内容、服务不可用和任务执行阶段。已有合法返回格式不匹配时，才使用原有的一次格式纠正；接口故障不通过新增提示词重试循环掩盖。策略改变与故障修复分别提交，修复关联到能失败的具体回归用例。没有直接证据时不新增自动切换、重试或特殊成员规则。
