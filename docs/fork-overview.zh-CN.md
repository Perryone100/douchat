状态核对日期：2026-10-14。后续分支、合并及发布状态以 GitHub 页面为准。

## 定位与上游关系

本仓库是 [thinkany-ai/douchat](https://github.com/thinkany-ai/douchat) 的社区 Fork，
基于上游 v0.1.24（`806316a0`）。保留原项目名称、来源及 [AGPL-3.0 许可证](../LICENSE)。

当前改动集中在群任务的模型请求与规划生命周期：减少任务在真正开始执行前反复超时的问题。
适用于不同项目、成员名称与职责配置，不要求固定的“老板—经理—员工”组织，也没有新增专用团队模式。

自定义模型、本地 CLI、记忆、群聊、工作区、工具权限和任务依赖执行是上游已有能力。
本 Fork 改进这些能力之间的规划与交接可靠性，不将上游功能列作新增成果。

## 已经改了什么

| 问题 | 修复分支的处理 |
| --- | --- |
| 原规划调用使用非流式响应，40/60 秒绝对期限可能中止仍在生成的模型 | 读取 OpenAI / Anthropic 流式文本及推理活动；以 60 秒无有效进度判断停滞，同时保留每轮 180 秒总预算。 |
| 保活消息可能被误当作模型工作 | 空心跳、角色、usage 等事件不重置进度期限；推理正文不进入规划返回值或诊断日志。 |
| 连接、认证或限流问题进入“修正 JSON”重试 | 区分传输错误与结构错误；真正的计划结构错误最多修正一次。 |
| 成员切换后仍调用同一个已失败的自定义后端 | 在同一次成员候选切换中，按服务配置和模型去重失败后端；不同本地配置保持独立。 |
| 开始工作前串行调用过多 | 默认成员协调直接生成完整计划，移除初始的个人发言分类前置调用。 |
| 规划耗时难以定位 | 记录首个有效进度和总规划耗时；补充可重复运行的回归与真实模型测试。 |
| 长对话重复背景挤占输出空间，成员只输出 1 token | 本地精确去重，仍接近上限时按需生成可恢复的交接摘要；预留回答空间，保存原文供查证，不静默丢弃旧回合。 |

DeepSeek 规划请求显式使用低推理及 JSON 输出，成员正式工作时仍使用各自保存的模型与思考设置。
已有的依赖关系执行、完成步骤重放、人工确认与工具权限继续保留。

详见修复分支中的 [规划实现与复现](https://github.com/Perryone100/douchat/blob/codex/fix-planning-timeouts/docs/group-planning-reliability.md)、
[上下文与成本](model-context-budget.md) 和 [版本记录](versions.zh-CN.md)。

## 从源码启动修复版

准备 Node.js 22.12+、npm 10+ 和可登录的 Douchat 账号。macOS 开发还需 Xcode Command Line Tools。
下面适用于新目录：

```bash
git clone --branch codex/fix-planning-timeouts https://github.com/Perryone100/douchat.git
cd douchat
npm ci
cp .env.example .env
npm run dev
```

已有源码目录：先保存自己的改动并检查 `git status`；确认 `origin` 指向本 Fork 后，再更新分支：

```bash
git remote -v
git fetch origin
git switch codex/fix-planning-timeouts
git pull --ff-only origin codex/fix-planning-timeouts
npm ci
npm run dev
```

若本 Fork 的远程名称是 `perry`，把上述 `origin` 换为 `perry`；若本地尚无修复分支，
使用 `git switch --track <远程名>/codex/fix-planning-timeouts` 创建跟踪分支。
更新前退出正在运行的开发客户端；已有 `.env` 时无需再次复制模板。

开发版的 macOS 数据目录是 `~/Library/Application Support/douchat-dev`，与正式安装版的
`~/Library/Application Support/douchat` 分开。更新源码不会要求重建智能体；迁移或切换版本前，
应在退出客户端后备份数据目录。不要通过删除数据目录来修复模型超时。

## 使用自己的模型与本地智能体

1. 在客户端设置中添加自定义模型服务，填写服务商提供的 API 地址、API Key 和模型 ID。
2. 创建或编辑智能体，选择该自定义服务；正式工作时的模型与思考强度按成员分别设置。
3. 使用本地智能体时，先确保对应 CLI 已安装、可被客户端检测且已经完成其自身登录。
4. 在“群决策服务”中选择“默认”，由群内协调成员使用其模型规划任务。若要让这条路径使用自有模型，
   也需要将可参与协调的成员配置为自有服务或本地智能体。
5. 把成员加入群，说明目标、资料、交付物及必要的先后依赖。不同项目用独立群或话题组织上下文。

“决策模型”选项中带有 Douchat 云端额度提示的服务仍会消耗其额度。
自有 API 按服务商规则计费；本地 CLI 受其自身账号授权与额度限制。Fork 不提供额外模型额度。

当前客户端仍依赖 Douchat 登录。选择自己的模型并不使账号、朋友同步、共享群等能力离线化；
首次登录的内置云端联系人等功能也仍属于上游云服务路径。
自定义模型的普通 API Key 不需要填入通用 `GATEWAY_*` 环境变量，优先使用客户端的模型配置界面。

## 仍然存在的边界

- 修复不会解决服务商宕机、网络中断、额度不足或无限长任务；规划仍有无进度及总时间上限。
- 若服务返回非流式 JSON，没有可观察的中间进度，仍会受无进度期限约束。
- 失败后端去重范围是同一次成员候选切换，不是跨所有请求的全局熔断器。
- 实际工作步骤继续使用原有执行、权限和恢复机制；没有因为规划重试而自动重放有副作用的工具操作。
- 客户端验收时曾出现 Douchat 云端好友同步的 TLS 连接错误，本地智能体群仍能完成任务；
  该云端连接问题没有在本次规划修复中解决，朋友及共享群同步仍可能受影响。
- 记忆、工具权限和任务结果质量仍需按项目配置及验证；模型给出“完成”文字不能代替真实产出或测试。
- 交接摘要不是无损压缩，触发时会产生正常模型用量；详见上下文文档。最新请求及其工具结果本身过大时仍可能明确停止。
