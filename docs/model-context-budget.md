# 长对话上下文：去重、交接摘要与原文查证

## 已确认的故障与恢复原因

2026-10-14 17:29（上海时间），一次群聊追问的规划在约 2.5 秒内完成，
但成员回复以 `length` 停止、只生成 1 token。日志记录未缓存输入 131,882、缓存输入 4,864。
客户端自定义模型元数据当时统一配置 128,000 token 窗口，底层 SDK 根据历史 usage
计算剩余输出空间，空间不足时把 `max_tokens` 压到 1。这不是此前规划阶段的超时故障。

成员没有可用输出时，运行时会丢弃该临时会话并让调度选择后续处理；后续新会话重新
加载较短的背景，因此可能正常回答。闲置 5 分钟、模型绑定改变、独立任务或简短发言
也会影响会话复用。恢复回答不表示长上下文风险消失，更不表示旧版本自动完成了语义压缩。

## 当前群聊怎样选取背景

`sharedGroupMessages` 优先选最新用户消息、调度关联消息，再从近到远补充，最后按原顺序发送。
正文累计最多 48,000 字符、单条最多 12,000 字符；这是字符上限，不是 token 上限。
人设/系统规则、群记忆、内部账户相关记忆、工具定义及调用结果另计。
持续复用的模型会话又保留每一轮请求和回复，造成同一份近期背景在不同轮次重复出现。
群聊背景选择本身不是对所有历史事实进行语义检索；早期独有要求仍需项目记忆、文档或历史证据补充。

## 新处理方式

1. 在实际托管模型调用之前检查输入，保留正常输出和安全余量。估算覆盖中文、图片与工具定义，
   结合已有真实 usage；它仍不是精确 tokenizer，模型元数据窗口也不代表服务商真实上限。
2. 对运行时生成的群聊背景做本地精确去重：只有 ID、内容和元数据完全相同且后面仍有一份的
   公共消息副本才从旧请求移除。保留独有旧要求、变化后的版本、旧任务指令、最新请求和工具链。
   此步骤不调用模型。
3. 去重后仍接近上限，才调用当前成员配置的模型生成结构化交接摘要：目标与约束、决策、
   已完成工作、待办、资料引用、不确定事项。摘要独立使用最小思考档和 4,096 输出上限，
   不改变正式工作的思考设置、不提供工具。一次压缩最多两个摘要请求，不做摘要修复重试循环。
4. 保存摘要和对应原文后，发送“历史交接摘要 + 保留的完整近期回合 + 当前请求/工具链”。
   后续复用同一摘要，直到剩余上下文再次需要压缩。原会话和聊天记录不改写。
5. 摘要及原文保存于本地数据库，按账号、会话、话题、成员和运行会话键隔离，支持重启后恢复。
   成员可用 `read_context_checkpoint` 分页读对应原文及图片；摘要链保留前一份记录 ID。
   清空/重置上下文、删除话题或聊天会清理对应记录，删除成员会级联清理其记录。
   回退旧版再升级时也会核验重置标记及消息锚点，不加载已经清空或重置的旧摘要。
6. 摘要不完整、请求超限或取消时不保存半成品，不回退到静默删除历史。当前请求和其工具链
   本身过大时明确报错，不拆开工具调用与结果，也不自动重做工具。
7. 清除发送副本中已不适用的历史 usage，防止 SDK 继续依据旧输入把输出压到 1。
   原记录的 usage 保留。空回复恢复仍最多一次，从现有工具结果继续，不再追加冗余用户提示。

这不是无损压缩，不能保证模型摘要保留所有细节。摘要作为历史证据而非新授权，当前要求优先；
事实和完成状态需要时回查原文或产物。本功能不改变本地 Codex 等 CLI 自身的压缩策略，
不自动共享成员的私有交接摘要，也不把所有历史群聊内容永久塞入每次请求。

## 成本与诊断

短对话、纯去重和复用摘要不新增摘要调用。触发语义压缩会产生正常模型用量；
每次摘要请求最多 4,096 输出 token，单次压缩最多两次调用，超出预算明确停止。
输入减少可能降低后续成本，但缓存命中改变、摘要及正常回答输出都影响账单，不能承诺零增量费用。

运行事件记录 `Model request context`、`Model context deduplicated`、`Context checkpoint usage`
和 `Model context compacted`，包括成员、估算输入规模及摘要实际用量，不记录密钥或把 SDK 零价格当作账单。
